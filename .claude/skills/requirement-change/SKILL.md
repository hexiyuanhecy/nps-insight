# 需求变更处理流程

## 触发条件
当用户输入包含"需求变更："前缀时触发。

## 执行步骤（严格按顺序）
1. **理解变更**: 复述用户的需求变更，确认理解正确
2. **更新 PRD**: 读取并更新 `.trae/documents/NPS-Insight-PRD.md`
   - 标记变更内容（使用 ✏️ 标记新增，使用 🗑️ 标记删除）
   - 更新功能列表和验收标准
3. **更新技术文档**: 更新 `.trae/documents/NPS-Insight-Tech-v2.md`
   - 更新受影响的 API 接口定义
   - 更新数据模型（如有变更）
   - 更新组件结构（如有变更）
4. **更新测试用例**: 更新相关测试文件
   - 新增功能的测试用例
   - 修改受影响功能的测试用例
5. **修改代码**: 按更新后的技术文档逐个修改代码文件
6. **运行测试**: 运行全量测试，确认所有测试通过
7. **输出变更摘要**:
   - 更新了哪些文档
   - 修改了哪些代码文件
   - 测试结果
   - 是否有遗留问题
