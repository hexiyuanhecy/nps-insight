# NPS 飞书多维表格 1:1 克隆 执行手册（专供编程AI执行·终稿）
> 执行对象：逻辑能力弱、易自作主张的编程AI
> 输入物料：`nps_bitable_full_meta.json`（源表完整元数据）
> 输出产物：飞书内一张结构完全一致的全新多维表格 + 标准化Lookup手动补配清单
> 核心铁则：**严格按步骤串行执行，禁止自行增减字段、修改参数、优化逻辑、并行请求，错一个字符都算失败**
> 已知官方限制：飞书API不支持创建 `type=19` Lookup查找字段，该类字段输出手动操作清单，禁止强行创建

## 核心总则（违反任意一条直接判定执行失败）
1.  **绝对禁止并行请求**：所有建表、建字段操作必须串行逐个执行，前一个请求返回成功后再发下一个，禁止使用 `Promise.all` 等并行方式，保证表/字段顺序与源表完全一致。
2.  **参数禁止自作删减**：创建字段的请求体只允许包含 `field_name`、`type`、`property` 三个字段，所有只读属性（`is_primary`/`is_extend`/`is_synced`）必须全部过滤，禁止透传。
3.  **property 空值规则**：若源字段 `property === null`，请求体中直接省略 `property` 字段，禁止传 `null`、禁止传空对象 `{}`。
4.  **单选选项ID必须完整保留**：单选/多选字段的 `options` 数组，每一项的 `id`、`name`、`color` 必须原封不动传入，禁止删减 `id` 字段，保证公式中选项ID引用生效。
5.  **主键禁止新建**：每张表有且仅有1个主键，新建空白表时飞书会自动生成默认主键，只能通过「修改字段」接口将默认主键改成源表主键配置，禁止重复创建主键字段。
6.  **Lookup 必须占位**：Lookup字段不能跳过不建，必须先创建同名文本字段占位，保证列顺序与源表完全一致；手动补配时先删占位字段，再在原位置创建查找。
7.  **请求限流强制生效**：每一次表/字段创建请求后，强制等待 300ms 再发下一个请求；遇 429 频控按 `Retry-After` 头等待，无该头则等待2秒重试，最多重试3次；4xx参数错误不重试，直接终止。
8.  **失败立即终止**：任意核心步骤（建表、建基础字段、建公式）失败，立即停止执行，开启回滚，禁止忽略错误继续往下跑。
9.  **公式ID精确替换**：公式内的表ID、字段ID必须用正则精确匹配替换，覆盖 `{fid}`、`$column[fid]`、`$field[fid]`、`$table[tid]` 四种格式，禁止全局字符串替换，避免ID子集误匹配。
10. **先自检再执行**：所有前置校验通过后才能开始创建表格，禁止边跑边校验，避免产生垃圾表格。

### 输入
newAppToken、源表元数据

### 执行步骤
1.  **严格按源JSON表的顺序串行创建**，禁止调整顺序、禁止并行。
2.  遍历每张源表：
    a. 取出旧表ID `oldTableId`、表名 `tableName`
    b. 请求方式：`POST`
    c. 请求地址：`/open-apis/bitable/v1/apps/${newAppToken}/tables`
    d. 请求体：
        ```typescript

          name: tableName,
          default_view_name: "默认视图"
        }
        ```
    e. 提取新表ID `newTableId`
    f. 写入全局映射字典：`tableIdMap[oldTableId] = newTableId`
    g. 强制等待 300ms，再处理下一张表

### 全局容器
```typescript
const tableIdMap: Record<string, string> = {}; // 旧表ID → 新表ID
```

### 校验点
- [ ] 成功创建 6 张数据表，表名与源表完全一致
- [ ] `tableIdMap` 包含全部 6 个旧表ID，每个都对应有效新表ID

## 阶段4：逐表创建字段（核心阶段，严格按顺序执行）
### 输入
newAppToken、tableIdMap、源表字段列表

### 全局容器
```typescript
const fieldIdMap: Record<string, string> = {};   // 旧字段ID → 新字段ID
const formulaFieldList: any[] = [];              // 暂存公式字段，延后创建
const lookupFieldList: any[] = [];               // 暂存Lookup字段，生成手动清单
```

### 执行步骤
按表顺序逐张处理，每张表执行以下 3 个子步骤：

#### 子步骤4.1：处理主键字段（禁止新建，只能修改）
1.  调用「获取字段列表」接口，读取新表的默认字段，找到默认主键的 `field_id`（通常是第一个字段，名称为“名称”）。
2.  在源表字段中找到 `is_primary = true` 的主键字段。
3.  调用「修改字段」接口，把默认主键修改为源主键的配置：
    - 请求方式：`PUT`
    - 请求地址：`/open-apis/bitable/v1/apps/${newAppToken}/tables/${newTableId}/fields/${默认主键ID}`
    - 请求体：仅包含 `field_name`、`type`、`property`，过滤所有只读属性
    - property 为 null 则省略该字段
4.  修改成功后，写入映射：`fieldIdMap[源主键field_id] = 默认主键ID`

#### 子步骤4.2：按顺序遍历剩余字段，分类处理
**严格按源字段数组原生顺序逐个处理，禁止排序、禁止并行**，每个字段执行分类判断：

1.  **若 type = 19（Lookup查找）**
    - 不创建真实查找字段，创建一个**同名字段，类型为文本（type=1）**，占住当前列位置
    - 创建成功后，将该字段完整信息推入 `lookupFieldList`，记录：旧表名、旧字段名、原列序号、源property
    - 占位字段ID**不写入** fieldIdMap（后续手动替换）

2.  **若 type = 20（公式）**
    - 暂不创建，将字段完整信息推入 `formulaFieldList`，记录所属新表ID
    - 跳过本次创建，继续下一个字段

3.  **若为基础字段（type=1/2/3/4/5/7）**
    - 构造请求体，**仅保留 field_name、type、property 三个字段**，其余全部删除
    - property 为 null 则省略 property 字段
    - 单选/多选字段的 options 必须完整保留 id、name、color，禁止删减
    - 深拷贝 property，禁止直接引用源对象
    - 调用创建字段接口
    - 成功后写入 `fieldIdMap[旧field_id] = 新field_id`
    - 强制等待 300ms

#### 子步骤4.3：单表字段数量校验
单表所有字段处理完成后，立即校验：
> 新表现有字段总数 = 源表字段总数
不通过立即终止，排查漏建/错建。

### 校验点
- [ ] 每张表字段数量与源表一致
- [ ] 主键字段名称、类型、属性与源表完全一致
- [ ] 所有基础字段类型、选项、格式与源表一致
- [ ] `fieldIdMap` 包含所有基础字段的旧→新映射
- [ ] Lookup占位字段全部创建，列顺序与源表一致

## 阶段5：批量创建公式字段 + 精确ID替换
### 输入
formulaFieldList、tableIdMap、fieldIdMap

### 执行步骤
**串行逐个创建**，禁止并行：
1.  取出每个公式字段的原始 `property.formula_expression`
2.  执行 ID 精确替换（顺序不能乱，必须用正则精确匹配，禁止全局replace）：
    a.  **替换表ID**：正则匹配 `\$table\[([^\]]+)\]`，将中括号内的旧表ID替换为 `tableIdMap` 中的新表ID
    b.  **替换字段ID**：分别匹配三种格式，全部替换：
        - `\{([fld][^\}]+)\}` （本表字段引用）
        - `\$column\[([^\]]+)\]` （跨表列引用）
        - `\$field\[([^\]]+)\]` （本表字段引用）
    c.  **选项ID不替换**：`$option[opt_xxx]` 保持原样，因为创建单选字段时已保留了原选项ID
3.  构造新 property：复制源 property，仅替换 `formula_expression` 为替换后的字符串
4.  调用创建字段接口，请求体仅包含 `field_name`、`type: 20`、`property`
5.  成功后写入 `fieldIdMap[旧field_id] = 新field_id`
6.  强制等待 300ms

### 校验点
- [ ] 所有公式字段创建成功，接口无报错
- [ ] 替换后的公式内，无任何残留的旧表ID、旧字段ID
- [ ] 打开新表格，公式字段无 #错误 标识
- [ ] `fieldIdMap` 包含所有公式字段映射

## 阶段6：生成 Lookup 字段手动补配标准化清单

### 清单格式要求（每个字段必须包含以下全部信息，禁止只给参数）
```
【字段序号：X / 字段名称：xxx】
所在数据表：xxx
原表列位置：第 X 列
查找类型：筛选式高级查找 / 关联式查找
操作步骤：
1. 进入【表名】→ 找到第 X 列的占位文本字段 → 删除该字段
2. 在原位置点击「+ 添加字段」→ 选择「查找」
3. 基础配置：
   - 目标数据表：xxx（表名）
   - 要返回的字段：xxx（字段名）
   - 聚合方式：xxx（拼接/计数/去重拼接）
4. 筛选配置：
   条件1：目标表.xxx 包含/等于 当前行.xxx
   条件2：xxx
   条件连接方式：且/或
```

### 聚合方式映射（严格对应）
- `roll_up = 0` → 拼接（LISTCOMBINE）
- `roll_up = 2` → 计数（COUNTA）
- `roll_up = 6` → 去重拼接（UNIQUE）

### 特殊说明（针对本次元数据）
> 本次所有Lookup均为**筛选式高级查找**，不依赖LINK关联字段，创建时直接选择目标表并配置筛选条件即可。

## 阶段8：异常处理与回滚规则
### 重试规则
1.  网络错误、5xx 服务端错误：自动重试 3 次，间隔 1 秒
2.  HTTP 429 频控：读取 `Retry-After` 响应头，等待对应秒数后重试；无该头则等待 2 秒重试，最多 3 次
3.  4xx 参数错误、权限错误：**不重试**，立即终止执行

### 回滚规则
1.  配置项 `ROLLBACK_ON_ERROR = true`（默认开启）
2.  触发条件：任意核心步骤（建表、建基础字段、建公式）失败且无法重试解决
3.  回滚操作：调用删除多维表格接口，删除已创建的新表格，不留垃圾数据
4.  回滚后输出完整错误日志：失败步骤、请求参数、返回错误信息

## 附录B：常见错误排查表
| 错误现象 | 排查方向 |
|----------|----------|
| 接口返回403无权限 | 1. 应用未开通bitable读写权限；2. 应用未添加为表格协作者；3. token过期 |
