## 1. 系统概述

### 1.1 什么是 NPS Insight？

NPS Insight 是一款基于飞书生态的 AI 驱动 NPS 反馈分析工具。它能自动收集用户反馈、智能打标签、深度分析 Top 问题，并生成周报/月报，帮助团队快速定位产品问题、提升用户满意度。

### 1.2 核心价值

- **自动化**：每周自动拉取反馈、AI 打标、发送周报，无需人工干预
- **智能化**：三级标签体系（Tag1/Tag2/Tag3）+ 标签自进化，持续优化分类
- **可视化**：飞书群消息卡片、多维表格仪表盘、月报文档，一目了然
- **大租户优先**：Top 问题排序优先考虑大客户反馈，聚焦核心用户痛点

### 1.3 系统架构图

```
用户反馈 → 数据拉取 → AI打标 → 飞书多维表格
                                    ↓
                            报通知 → 飞书群
                                    ↓
                            月分析 → Top问题表 + 会议文档
```

## 2. 快速开始（首次配置）

### 2.1 前置条件

1. 飞书账号（企业管理员权限）
2. 飞书自建应用已创建（获取 App ID 和 App Secret）
3. 飞书多维表格已创建（或由系统自动创建）
4. AI API 密钥（如 AgnesAI、OpenAI 等）

### 2.2 进入配置中心

在飞书应用中打开 NPS Insight，点击右上角「配置中心」进入。

配置中心分为三个 Tab：

| Tab | 名称 | 功能 |
|-----|------|------|
| Tab 1 | 数据源配置 | 配置反馈数据来源（API 或 Excel） |
| Tab 2 | 飞书集成 | 配置飞书应用、多维表格、通知群 |
| Tab 3 | AI 与定时任务 | 配置 AI 密钥、置信度阈值、定时任务周期 |

### 2.3 配置步骤（顺序建议）

#### 步骤 1：配置飞书集成（Tab 2）

1. **飞书应用配置**
   - 输入 App ID、App Secret
   - 点击「测试连接」验证有效性
   - 成功后显示绿色 Toast 提示

2. **多维表格配置**
   - 输入多维表格 App Token（格式：`https://www.feishu.cn/base/{app_token}`）
   - 点击「测试连接」验证表格访问权限
   - 如表格不存在，点击「自动创建表格」让系统初始化

3. **通知群配置**
   - 输入飞书群 Chat ID（从群设置获取）
   - 选择通知方式：群消息或私聊

#### 步骤 2：配置数据源（Tab 1）

**方式 A：API 拉取（推荐）**

1. 输入反馈 API 地址（如 `https://api.example.com/feedbacks`）
2. 输入 API Key（用于鉴权）
3. 配置时间范围规则（如 `last_7_days`）
4. 点击「测试拉取」验证数据格式

**方式 B：Excel 上传**

1. 准备 Excel 文件，格式要求：
   - 必含列：反馈ID、租户ID、租户名称、评分、反馈原文、创建时间
   - 可选列：租户规模、不满意原因、来源
2. 点击「上传 Excel」按钮
3. 上传成功后自动触发打标流程

> **优先级规则**：Excel 上传优先级高于 API 配置。若上传了 Excel，系统优先分析 Excel 数据。

#### 步骤 3：配置 AI 与定时任务（Tab 3）

1. **AI 配置**
   - 选择 AI 模型（如 AgnesAI、OpenAI）
   - 输入 API Key 和 Base URL
   - 点击「测试 AI 连接」验证有效性

2. **置信度阈值**
   - 默认 0.8，可调整（0-1）
   - 置信度低于阈值的反馈标记为「待审核」

3. **定时任务**
   - 周打标：默认每周一 09:00，可调整周期和时间
   - 月分析：默认每月 1 日 00:00，可调整周期和时间

4. 点击「保存配置」完成全部配置

## 3. 日常操作流程

### 3.1 周打标流程

**触发方式（3 种）**：

| 方式 | 操作步骤 | 适用场景 |
|------|---------|---------|
| 自动触发 | 定时任务到达时间自动执行 | 正常运维，无需操作 |
| 手动触发 | 配置中心点击「立即执行周打标」 | 紧急补充数据、测试验证 |
| Bot 触发 | 飞书群输入 `/nps tag` | 远程操作、移动端触发 |

**流程步骤（7 步，全自动）**：

```
1. 获取反馈（API拉取/Excel读取）
2. 去重（过滤已存在反馈）
3. 补充租户名（新租户自动写入租户表）
4. 语言翻译（非中文自动翻译）
5. AI 打标（Tag1/Tag2/Tag3 + 置信度 + 需查日志）
6. 写入多维表格
7. 发送周报通知到飞书群
```

**预计耗时**：100 条反馈约 5-8 分钟

### 3.2 月分析流程

**触发方式（2 种）**：

| 方式 | 操作步骤 | 适用场景 |
|------|---------|---------|
| 自动触发 | 定时任务到达时间自动执行 | 正常运维 |
| 手动触发 | 配置中心点击「立即执行月分析」 | 紧急生成月报、测试验证 |

**流程步骤（5 步，全自动）**：

```
1. 标签自进化（合并相似标签、拆分过细标签）
2. 生成 Top 问题表（按大租户反馈数排序）
3. 公式权重反哺（读取用户调整的权重）
4. 生成会议文档（飞书 Docx）
5. 发送月报通知到飞书群
```

**预计耗时**：约 3-10 分钟（取决于数据量和标签复杂度）

## 4. Bot 命令使用

在飞书群中 @NPS Insight 机器人，输入以下命令：

| 命令 | 功能 | 示例 |
|------|------|------|
| `/nps help` | 显示帮助信息 | `@机器人 /nps help` |
| `/nps status` | 查看当前配置状态 | `@机器人 /nps status` |
| `/nps tag` | 手动触发周打标 | `@机器人 /nps tag` |
| `/nps analyze` | 手动触发月分析 | `@机器人 /nps analyze` |
| `/nps config` | 查看配置摘要 | `@机器人 /nps config` |

**注意事项**：
- 命令必须在飞书群中发送，私聊不支持
- 同一配置 10 分钟内仅允许 1 个任务运行，重复触发会有提示
- 任务执行期间可在飞书群收到实时进度通知

## 5. 周报与月报解读

### 5.1 周报消息卡片

每周打标完成后，飞书群收到消息卡片：

```
📊 【Feelgood 打标周报】2026 年第 27 周

本周拉取：77 条负反馈
AI 已完成打标，待审核：2 条
需查日志：38 条

📋 Top 5 问题：
1. 打卡定位失败 (打卡异常与故障) - 11 次 (14%)
2. 希望支持批量打卡 (打卡异常与故障) - 10 次 (13%)
...

📈 评分分布：1 分占 26% | 2-3 分占 56% | 4-5 分占 18%

[审核标签]  [完整看板]  [查看日志平台]
```

**字段解读**：

| 字段 | 含义 | 处理建议 |
|------|------|---------|
| 本周拉取 | 本周新增反馈总数 | 正常监控 |
| 待审核 | AI 置信度低于阈值，需人工确认 | 点击「审核标签」快速处理 |
| 需查日志 | 描述技术异常但无法判断原因 | 点击「查看日志平台」排查 |
| Top 5 问题 | 本周高频问题排序 | 关注前 3 条，优先处理 |
| 评分分布 | 用户满意度分布 | 关注 1 分占比，趋势分析 |

### 5.2 月报消息卡片

每月分析完成后，飞书群收到消息卡片：

```
📈 【Feelgood 月度分析】2026 年 7 月

📋 Top 问题概览：
1. 打卡定位失败 (打卡异常与故障) - 85 次，大租户占 40%
2. 提交后页面报错 (休假流程故障修复) - 45 次，大租户占 30%
...

🔄 本期标签自进化：合并标签 3 组，拆分标签 2 组

[Top 问题表]  [查看会议文档]  [可视化仪表盘]
```

**字段解读**：

| 字段 | 含义 | 处理建议 |
|------|------|---------|
| 大租户占比 | A4/A5/A6 租户反馈占比 | 大租户占比高的优先处理 |
| 标签自进化 | AI 自动合并/拆分标签 | 查看会议文档确认变更 |

## 6. 审核与人工干预

### 6.1 审核待打标反馈

**触发场景**：周报显示「待审核：XX 条」

**操作步骤**：

1. 点击周报卡片「审核标签」按钮
2. 自动打开多维表格，已筛选「待审核」反馈
3. 检查 Tag1/Tag2/Tag3 是否合理
4. 人工修正标签（点击标签字段编辑）
5. 修改后「待审核」字段自动变为「否」

**审核标准**：
- Tag1：是否符合问题性质（功能优化/疑似Bug/用户教育等）
- Tag2：是否归属正确模块
- Tag3：是否从用户原话提炼，具体明确

### 6.2 排查需查日志反馈

**触发场景**：周报显示「需查日志：XX 条」

**操作步骤**：

1. 点击周报卡片「查看日志平台」按钮（仅在有需查日志时显示）
2. 跳转到配置的日志平台（如 Splunk、ELK）
3. 根据反馈时间、租户ID、用户ID 搜索日志
4. 定位根本原因后，在多维表格「备注」字段记录结论
5. 修改「需查日志」字段为「否」

## 7. Top 问题表与会议文档

### 7.1 Top 问题表字段说明

打开多维表格 → Top 问题表，字段如下：

| 字段 | 含义 | 来源 |
|------|------|------|
| Tag2 | 功能模块 | AI 打标 |
| Tag3 | 具体问题 | AI 打标 |
| 总反馈数 | 本月该问题反馈总数 | 系统统计 |
| 大租户反馈数 | A4/A5/A6 租户反馈数 | 系统统计 |
| A4/A5/A6 数量 | 各规模租户详细数据 | 系统统计 |
| 综合评分 | 排序权重得分 | 公式计算 |
| 负责人 | 问题处理责任人 | **人工填写** |
| 解决方案 | 处理方案描述 | **人工填写** |
| 状态 | 处理进度（待处理/进行中/已解决） | **人工填写** |
| 本期新增数 | 本月新增反馈数 | 系统统计 |

> **注意**：系统字段（总反馈数、大租户反馈数等）每次月分析会更新，**人工字段（负责人、解决方案等）不会被覆盖**，放心填写。

### 7.2 会议文档内容

月分析自动生成飞书文档，包含：

1. **数据概览**：总反馈数、NPS 分数、评分分布
2. **Top 问题详情**：每个 Top 问题的数据、典型反馈原文、建议关注点
3. **标签自进化记录**：合并/拆分的标签详情、影响范围
4. **下一步建议**：AI 生成的处理建议（可选）

## 8. 常见问题与解决方案

### 8.1 配置问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 测试连接失败 | App Secret 错误或权限不足 | 检查飞书应用权限，确保有 bitable:read、bitable:write、im:message 权限 |
| 多维表格访问失败 | 未添加为表格协作者 | 在飞书多维表格设置中添加应用为协作者（full_access） |
| Excel 上传失败 | 格式不匹配或字段缺失 | 检查 Excel 是否含必填列：反馈ID、租户ID、评分、反馈原文、创建时间 |

### 8.2 打标问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| AI 打标超时 | 批次过大或网络问题 | 系统自动重试，无需干预；如持续失败检查 AI API 配置 |
| 置信度普遍偏低 | Prompt 不匹配业务场景 | 调整置信度阈值或联系管理员优化 Prompt |
| 标签创建失败 | 多选字段选项上限 | 飞书多维表格多选字段最多 5000 个选项，需手动清理冷门标签 |

### 8.3 通知问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 飞书群未收到通知 | Chat ID 错误或机器人未入群 | 检查群 Chat ID，确保机器人已加入目标群 |
| 通知卡片显示不全 | 群消息卡片被折叠 | 点击卡片展开查看完整内容 |

### 8.4 定时任务问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 定时任务未触发 | Cron 配置错误或服务未部署 | 检查 Tab 3 定时任务配置，确认服务已部署到 Vercel 或腾讯云 |
| 任务重复触发 | 手动触发与定时触发冲突 | 同一配置 10 分钟内仅允许 1 个任务，等待当前任务完成 |

## 9. 附录

### 9.1 三级标签体系说明

| 层级 | 名称 | 作用 | 示例 |
|------|------|------|------|
| Tag1 | 问题性质 | 决定处理流程 | 功能优化、疑似Bug、用户教育、性能提升、安全问题、体验问题、其他 |
| Tag2 | 功能模块 | 归属业务域 | 打卡异常与故障、休假流程故障修复、统计报表导出、审批流程 |
| Tag3 | 具体问题 | 精确描述现象 | 打卡定位失败、提交后页面报错、年假折算规则不透明 |

### 9.2 大租户定义

- **A4**：员工数 100-500 人
- **A5**：员工数 500-1000 人
- **A6**：员工数 >1000 人

大租户反馈在 Top 问题排序中权重占 30%，优先关注核心客户痛点。
