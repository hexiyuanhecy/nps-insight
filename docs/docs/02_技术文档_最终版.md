## 1. 技术架构

### 1.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Next.js 14 + TypeScript + Tailwind CSS | 配置中心页面 |
| 后端 | Next.js API Routes | 统一处理定时任务、Bot 回调、配置接口 |
| AI 服务 | AgnesAI（默认）/ 自定义 OpenAI 兼容接口 | 可配置切换 |
| 数据存储 | 飞书多维表格 + Vercel KV | 表格存业务数据，KV 存用户配置 |
| 定时任务 | Vercel Cron Jobs | 周度拉取打标、月度分析 |
| 消息通知 | 飞书自建应用 Bot | 消息卡片推送 |
| 部署 | Vercel | Serverless 自动扩缩容 |

### 1.2 系统架构图

### 1.3 核心原则

- **Adapter 模式**：所有外部依赖（存储、通知、文档、数据源）通过接口抽象，业务逻辑不直接依赖飞书
- **飞书原生优先**：计算、统计、可视化均使用飞书多维表格原生能力
- **批量写入**：所有数据在内存中组装完毕后一次性写入飞书表格
- **多用户隔离**：每个用户独立配置、独立表格、独立通知群
- **标签缓存**：标签体系 5 分钟内存缓存
- **直接函数调用**：内部任务使用直接函数调用，避免 HTTP fetch 死锁

### 3.3 编辑模式交互

**只读模式（默认）**：
- 所有输入框 disabled
- 右上角显示「编辑」按钮
- 周打标/月分析按钮始终可点击

**编辑模式**：
- 所有输入框 enabled
- 右上角显示「保存」按钮
- 点击「保存」后返回只读模式

**独立 loading**：
- 周打标按钮 loading 不影响其他按钮
- 月分析按钮 loading 不影响其他按钮
- 保存按钮 loading 不影响打标按钮

## 4. 周同步任务（sync-task.ts）

### 4.1 核心函数

```typescript
// 入口函数，供 route.ts 和 config/route.ts 直接调用
export async function runSyncTask(): Promise<SyncResult>
```

### 4.2 执行流程

```
runSyncTask()
├── runSyncTaskSingleUser() / runSyncTaskForUser(ownerId)
│   ├── syncExternalData()
│   │   ├── AdapterFactory.create(config)
│   │   ├── adapter.fetchData(start, end)
│   │   ├── getExistingFeedbackIds() // 去重
│   │   └── bitableClient.batchCreateRecords()
│   ├── autoTagFeedbacks()
│   │   ├── getCachedTags() // 5分钟缓存
│   │   ├── batchAnalyzeFeedbacks()
│   │   ├── ensureTagExists() // 确保标签存在
│   │   └── batchUpdateRecords()
│   ├── generateDailyReport()
│   ├── sendNotification() // 发送周报卡片
│   └── generateWeeklyDoc() // 生成周报文档
└── sendErrorNotify() // 失败时发送错误卡片
```

### 4.3 避免 HTTP fetch 死锁

**问题**：在 Next.js 单进程开发模式下，API route 通过 HTTP fetch 调用自己会导致死锁。

**解决方案**：
- 创建 `sync-task.ts` 封装核心逻辑
- API route 只做 HTTP 入口处理
- 内部调用（如配置中心触发）直接调用 `runSyncTask()` 函数
- 不再通过 HTTP fetch 调用自己的 API

## 6. 飞书 Bot 消息卡片

### 6.1 卡片类型

| 卡片 | 函数 | 用途 |
|------|------|------|
| 周报卡片 | `createWeeklyReportCard()` | 每周打标完成通知 |
| 月报卡片 | `createMonthlyReportCard()` | 每月分析完成通知 |
| 错误通知 | `createErrorNotifyCard()` | 任务失败通知 |
| NPS分析 | `createAnalysisCard()` | 月度 NPS 报告 |
| 帮助卡片 | `createHelpCard()` | `/nps help` 命令 |

### 6.2 错误通知卡片

```typescript
// 创建错误通知卡片
createErrorNotifyCard({
  taskType: '周打标' | '月分析' | '手动同步',
  errorMessage: string,
  executedAt?: string
})

// 发送错误通知
sendErrorNotify(chatId, taskType, errorMessage)
```

任务执行失败时自动调用，发送到配置的飞书群。

## 7. 配置存储

### 7.1 KV 存储结构

**配置键**：`config:{ownerUserId}`
**映射键**：`userConfigMapping:{userId}` → `ownerUserId`

### 7.2 配置数据结构

```typescript
interface StoredConfig {
  version: number;
  ownerUserId: string;
  feishu: {
    appId: string;
    appSecret: string;
  };
  bitable: {
    mode: string;
    appToken: string;
    url: string;
    status: 'unset' | 'linked';
  };
  dataSource: {
    apiUrl: string;
    apiKey: string;
    queryParams: string;
    timeRule: string;
  };
  webhook: { url: string };
  ai: {
    provider: string;
    apiKey: string;
    baseUrl: string;
    model: string;
    modelVersion: string;
  };
  tag1: Array<{ name: string; definition: string; enabled: boolean }>;
  tag2Init: string;
  tagging: {
    confidenceThreshold: number;
    largeTenantLevels: string[];
  };
  schedule: {
    syncUnit: string;
    syncEvery: number;
    syncTime: string;
    syncWeekDay: number;
    syncMonthDay: number;
    analysisUnit: string;
    analysisEvery: number;
    analysisTime: string;
    analysisWeekDay: number;
    analysisMonthDay: number;
    devMode: boolean;
  };
  logPlatform: { urlTemplate: string };
  notification: {
    chatIds: string;
    adminUserIds: string;
  };
}
```

### 7.3 敏感字段加密

使用 AES-256-GCM 加密：
- **加密字段**：`feishu.appSecret`、`dataSource.apiKey`、`ai.apiKey`
- **格式**：`encrypted:{base64(iv + ciphertext + authTag)}`
