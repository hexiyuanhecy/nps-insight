# 核心流程 - PRD 基准清单

**来源文档**：prd-v2.md 第5章
**生成日期**：2026-06-25

---

## PRD-FLOW-001
- **优先级**：P0
- **功能点**：周打标任务触发方式
- **PRD原文**：
  > 数据拉取与 AI 打标（每周）
  > 触发：用户配置的定时任务，默认每周一 09:00 自动执行。也可通过 Bot 对话手动触发。
- **验收标准**：
  - 支持定时任务自动触发（默认每周一09:00）
  - 支持通过Bot对话手动触发
  - 定时时间可配置
  - 触发后能正常执行完整打标流程

## PRD-FLOW-002
- **优先级**：P0
- **功能点**：数据源模式 - API拉取
- **PRD原文**：
  > 数据源模式：系统支持两种数据源接入方式：
  > - API 拉取：调用配置的接口地址，使用 API Key 和时间范围规则自动拉取。
  > - Excel 上传：用户手动上传 Excel 文件。
- **验收标准**：
  - 支持API拉取模式
  - 可配置接口地址
  - 可配置API Key
  - 可配置时间范围规则
  - 能成功拉取反馈数据

## PRD-FLOW-003
- **优先级**：P0
- **功能点**：数据源模式 - Excel上传
- **PRD原文**：
  > Excel 上传：用户手动上传 Excel 文件。
- **验收标准**：
  - 支持Excel文件上传
  - 能正确解析Excel中的反馈数据
  - 上传后可用于打标

## PRD-FLOW-004
- **优先级**：P0
- **功能点**：数据源优先级规则
- **PRD原文**：
  > 优先级规则：Excel 上传具有最高优先级。若用户上传了 Excel 文件，系统优先分析 Excel 数据，忽略 API 配置。Excel 无数据或未上传时，才走 API 拉取流程。
- **验收标准**：
  - Excel上传优先级高于API配置
  - 已上传Excel时，优先使用Excel数据
  - 无Excel数据或未上传时，走API拉取
  - 优先级逻辑正确，不会混用两种数据源

## PRD-FLOW-005
- **优先级**：P1
- **功能点**：Excel上传三种入口
- **PRD原文**：
  > Excel 上传的三种入口：
  > 1. 配置页上传：用户在配置中心 Tab 1 上传 Excel 文件，上传后自动触发打标流程。
  > 2. 人工导入后对话执行：用户先在配置页上传 Excel，然后在 Bot 群聊中输入指令手动触发打标。
  > 3. Bot 对话直接导入并执行：用户在 Bot 群聊中发送文件并 @机器人，机器人接收文件后自动导入并执行打标。
- **验收标准**：
  - 支持配置页上传Excel，上传后自动触发打标
  - 支持配置页上传后，通过Bot指令手动触发打标
  - 支持Bot群聊中直接发送文件并@机器人，自动导入并执行打标
  - 三种入口都能正常完成打标

## PRD-FLOW-009
- **优先级**：P1
- **功能点**：流程步骤4 - 语言翻译
- **PRD原文**：
  > 4. 语言翻译：系统自动检测反馈原文语言。若为非中文，AI 自动将其翻译为中文，并记录在"翻译后文本"字段。后续分析基于中文内容进行。
- **验收标准**：
  - 能自动检测反馈原文语言
  - 非中文内容自动翻译为中文
  - 翻译结果记录在"翻译后文本"字段
  - 中文内容不翻译，翻译后文本字段为空或与原文一致
  - 后续AI分析基于中文内容

## PRD-FLOW-010
- **优先级**：P0
- **功能点**：流程步骤5 - AI打标
- **PRD原文**：
  > 5. AI 打标：AI 逐批分析反馈，给出 Tag1/Tag2/Tag3 标签、置信度、是否需要查日志。
  >    - 标签优先匹配已有标签，无则自动创建。
  >    - 置信度低于阈值或 AI 觉得拿不准的，标记为"待审核"。
  >    - 描述卡顿/白屏等技术现象且无法从文字判断原因的，标记为"需查日志"。
- **验收标准**：
  - AI能逐批分析反馈
  - 输出Tag1/Tag2/Tag3标签
  - 输出置信度数值（0-1）
  - 输出是否需要查日志标记
  - 标签优先匹配已有标签，无匹配则自动创建新标签
  - 置信度低于阈值的标记为"待审核"
  - 描述卡顿/白屏等技术现象且无法判断原因的，标记为"需查日志"

## PRD-FLOW-014
- **优先级**：P1
- **功能点**：月度流程1 - 标签自进化
- **PRD原文**：
  > 1. 标签自进化（先于 Top 问题分析执行）：
  >    - 合并：发现两个同层级标签语义几乎相同，AI 自动合并，保留高频名称，更新所有历史反馈的引用。
  >    - 拆分：发现某 Tag2 下的 Tag3 超过 10 个且能明显分成多类，AI 自动拆分成更细的 Tag2，迁移对应 Tag3。
  >    - 冷门标签保留，不做处理。
- **验收标准**：
  - 标签自进化先于Top问题分析执行
  - 能自动合并语义几乎相同的同层级标签
  - 合并后保留高频名称
  - 合并后更新所有历史反馈的引用
  - 某Tag2下Tag3超过10个且能明显分类的，自动拆分成更细的Tag2
  - 拆分后迁移对应Tag3
  - 冷门标签不做处理，保留原样

## PRD-FLOW-015
- **优先级**：P0
- **功能点**：月度流程2 - 生成Top问题表
- **PRD原文**：
  > 2. 生成 Top 问题表：基于进化后的标签，统计每个 Tag2+Tag3 组合的反馈数，按大租户反馈数降序排列，取前 20-30 条写入表格。已存在的问题只更新"本期新增数"，绝不覆盖人工填写的字段。
- **验收标准**：
  - 基于进化后的标签统计
  - 以Tag2+Tag3组合为统计单位
  - 按大租户反馈数降序排列
  - 取前20-30条写入Top问题表
  - 已存在问题只更新"本周期新增"等系统字段
  - 绝不覆盖人工填写的字段
  - 新问题新增一行
