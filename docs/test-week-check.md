# 周打标流程 终极可落地验收表
## 核心修改说明
1.  每个节点新增**打标前基准状态**、**打标后强制数据状态**，明确执行前后的表格变化，从根源避免执行后表空
2.  所有验证标准均为**可代码编程校验**的硬规则，无模糊描述，编程AI可直接写校验脚本
3.  每个节点新增**空表/数据丢失排查校验点**，精准定位执行后表空的根因
4.  明确每个字段的写入要求、关联关系，彻底解决标签、反馈数据写入失败的问题

## 全流程执行后 最终数据校验清单（编程AI必须执行，彻底解决空表问题）
执行完周打标全流程后，必须通过以下所有校验，才算测试通过，任意一项不通过，直接标记测试失败，输出错误原因：
| 校验项 | 校验规则 | 不通过根因定位 |
| :--- | :--- | :--- |
| 1. 反馈列表校验 | 多维表格反馈列表新增行数 = 本次去重后的批次反馈数量 | 新增行数=0 → 数据写入完全失败，表空<br>新增行数＜批次数量 → 部分数据写入丢失 |
| 2. 标签表校验 | Tag2/Tag3表新增行数 = AI打标产生的新增标签数量 | 新增行数=0 → 无新增标签写入，标签表空<br>新增行数＜实际新增标签数量 → 部分标签写入丢失 |
| 3. 租户信息表校验 | 租户信息表新增行数 = 本次识别的新租户数量 | 新增行数＜实际新租户数量 → 租户信息写入失败 |
| 4. 字段完整性校验 | 反馈列表新增行的所有必填字段无空值：反馈ID、租户ID、租户名称、反馈原文、Tag1/Tag2/Tag3、打标状态 | 存在空值 → 字段写入失败，数据不完整 |
| 5. 标签关联校验 | 反馈列表的Tag1/Tag2/Tag3字段为关联类型，可正常跳转对应标签表 | 为纯文本 → 标签关联写入错误，后续统计失效 |
| 6. 打标状态校验 | 所有新增行的打标状态统一为「已打标」 | 存在未更新状态 → 写入流程未完成 |
| 7. 周报文档校验 | 飞书文档已成功创建，标题包含周期标识，内容完整 | 文档未创建 → 文档生成流程失败 |
| 8. Bot通知校验 | 配置的通知群已收到正确的周报消息卡片 | 未收到消息 → Bot通知流程失败 |

## 补充：编程AI执行测试的固定步骤
1.  先执行前置配置校验：确认飞书配置、数据源配置、AI模型配置、通知群配置已完整保存，飞书表格已绑定
2.  触发周打标任务（优先使用配置页「立即执行」按钮，可追踪日志）
3.  实时监控任务运行日志，定位任务终止/报错的节点
4.  全流程执行完成后，按上述最终校验清单逐项校验
5.  任意一项校验不通过，输出错误节点、错误原因、修复建议，重新执行测试
6.  所有校验项通过，标记周打标测试通过，输出完整测试报告
