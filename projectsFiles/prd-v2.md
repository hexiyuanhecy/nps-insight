# NPS Insight 产品需求文档

**版本**：v2
**日期**：2026-06-22

---

## 1. 产品定位

NPS Insight 是一款基于飞书多维表格的 AI 用户反馈分析工具。AI 自动拉取数据、打标签、生成图表与报告；人工在表格中审核标签，基于统计结果推动问题解决。

**核心原则**：
- 一条反馈可能同时包含多个问题，标签均支持多选。
- 反馈列表中的标签全部从标签体系表**引用**，不存文本。
- 租户信息**按需自动补充**，仅当出现新租户时才新增。
- 不同用户的配置和数据**完全隔离**，敏感信息加密存储。

---

## 2. 用户与权限

### 2.1 用户识别
使用飞书用户 ID 作为唯一标识。在飞书应用内自动获取身份，浏览器访问则通过飞书 OAuth 登录后获取，无需额外注册。

### 2.2 角色与权限

| 角色 | 权限 |
|------|------|
| **配置所有者** | 首次创建配置的人。可修改所有配置项，包括增删管理员 |
| **管理员** | 可修改除“管理员列表”外的所有配置项 |

一个配置即一个独立工作区，绑定独立的多维表格、数据源和通知群。所有用户的密钥、数据源地址等信息均需加密存储，不同用户之间数据完全隔离，管理员仅能操作被授权的配置。

## 3. 数据存储设计

所有数据存储在飞书多维表格中，共 6 张数据表 + 文档 + 仪表盘。

### 3.1 反馈列表
存储所有用户反馈及 AI 打标结果。

**核心字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 反馈ID | Text | 唯一标识 |
| 租户ID | Text | 租户唯一标识 |
| 租户名称 | Text | 自动关联租户信息表显示 |
| 租户规模 | SingleSelect | A1-A6 |
| 用户ID | Text | 提交反馈的用户ID |
| 用户名称 | Text | 提交反馈的用户名称 |
| 创建时间 | DateTime | 用户提交反馈的时间 |
| 不满意原因 | MultiSelect | 系统卡顿、界面不美观、功能缺失、打开速度慢、其他、缺少功能 |
| 反馈原文 | Text | 用户输入的文字内容 |
| 翻译后文本 | Text | 非中文内容经 AI 翻译后的结果 |
| 评分 | Number | 1-5 分 |
| 反馈平台 | Text | 如小程序打卡、Web 端 |
| **Tag1** | Relation | 关联 Tag1 表（多选） |
| **Tag2** | Relation | 关联 Tag2 表（多选） |
| **Tag3** | Relation | 关联 Tag3 表（多选） |
| AI 置信度 | Number | 0-1 的数值 |
| 需查日志 | Checkbox | 标记是否需要排查日志 |
| 待审核 | Checkbox | 标记是否需要人工复核 |
| 打标状态 | SingleSelect | `未打标` / `已打标` |

### 3.2 标签体系

标签体系分为三张子表，每张表均自动统计使用情况。

**Tag1 表（问题性质）**

| 字段 | 类型 | 说明 |
|------|------|------|
| tagId | Text | 唯一标识 |
| 标签名称 | Text | 如“疑似Bug” |
| 定义说明 | Text | 标签的详细解释 |
| 总使用次数 | Formula | `COUNTA(关联(反馈列表.Tag1))` |
| 大租户使用次数 | Formula | `COUNTA(FILTER(关联(反馈列表.Tag1), 反馈列表.租户规模 IN ["A4", "A5", "A6"]))` |
| 大租户占比 | Formula | `IF(使用次数 > 0, 大租户数 / 使用次数, 0)` |
| 平均评分 | Formula | `AVERAGE(关联(反馈列表.Tag1).评分)` |

**默认 7 个 Tag1**：疑似Bug、功能优化、界面改进、性能提升、用户教育、安全合规、无效反馈。

**Tag2 表（功能模块）**

| 字段 | 类型 | 说明 |
|------|------|------|
| tagId | Text | 唯一标识 |
| 标签名称 | Text | 如“打卡模块” |
| 所属一级标签 | Relation | 关联到 Tag1 表（可选） |
| 总使用次数 | Formula | `COUNTA(关联(反馈列表.Tag2))` |
| 大租户使用次数 | Formula | `COUNTA(FILTER(关联(反馈列表.Tag2), 反馈列表.租户规模 IN ["A4", "A5", "A6"]))` |
| 大租户占比 | Formula | `IF(使用次数 > 0, 大租户数 / 使用次数, 0)` |
| 平均评分 | Formula | `AVERAGE(关联(反馈列表.Tag2).评分)` |
| 下级 Tag3 数量 | Formula | `COUNTA(关联(Tag3表.所属二级标签))` |

**Tag3 表（具体问题）**

| 字段 | 类型 | 说明 |
|------|------|------|
| tagId | Text | 唯一标识 |
| 标签名称 | Text | 如“定位失败” |
| 所属二级标签 | Relation | 关联到 Tag2 表（必填） |
| 总使用次数 | Formula | `COUNTA(关联(反馈列表.Tag3))` |
| 大租户使用次数 | Formula | `COUNTA(FILTER(关联(反馈列表.Tag3), 反馈列表.租户规模 IN ["A4", "A5", "A6"]))` |
| 大租户占比 | Formula | `IF(使用次数 > 0, 大租户数 / 使用次数, 0)` |
| 平均评分 | Formula | `AVERAGE(关联(反馈列表.Tag3).评分)` |

### 3.3 租户信息表

| 字段 | 类型 | 说明 |
|------|------|------|
| 租户ID | Text | 唯一标识 |
| 租户名称 | Text | 公司/组织名称 |
| 规模 | SingleSelect | A1 - A6 |
| 是否企业版 | Checkbox | 是否为企业版用户 |
| 联系人 | Text | 联系人姓名 |
| 联系邮箱 | Text | 联系邮箱地址 |
| 日志平台 | Text | 日志查询平台地址 |
| 日志端点 | Text | 日志查询端点 |
| 创建时间 | DateTime | 记录创建时间 |

**补充规则**：当反馈列表中出现新租户时，系统自动查询其名称并写入此表。

### 3.4 Top 问题表（周期分析表）
每次月度分析的累积结果。

| 字段 | 类型 | 说明 |
|------|------|------|
| 所属模块 | Relation | 关联 Tag2 表（单选） |
| 具体问题 | Relation | 关联 Tag3 表（多选） |
| 问题标识 | Text | `tag2Name||tag3Name` |
| 总反馈数 | Number | 累计反馈数 |
| 本周期新增 | Number | 本月新增反馈数 |
| A4反馈数 | Number | A4 规模租户反馈数 |
| A5反馈数 | Number | A5 规模租户反馈数 |
| A6反馈数 | Number | A6 规模租户反馈数 |
| 大租户反馈数 | Number | A4+A5+A6 合计 |
| 大租户占比 | Number | 大租户反馈数 ÷ 总反馈数 |
| 平均分 | Number | 相关反馈平均分 |
| 人工综合排序 | Number | 仅供人工填写，系统永不覆盖 |
| 负责人 | Text | 仅供人工填写，系统永不覆盖 |
| 解决方案 | Text | 仅供人工填写，系统永不覆盖 |
| 状态 | SingleSelect | `待讨论`/`已排期`/`已上线`/`验证中` |
| 迭代周期 | SingleSelect | `Sprint 1`/`Sprint 2`/`Sprint 3+`/`待定` |

**生成规则**：
- 一个 Top 问题 = Tag2 + Tag3 组合。
- 按大租户反馈总数降序排列，取前 20-30 条。
- 首次全量写入。后续每次分析，若问题已存在（通过 Tag2+Tag3 组合识别），仅更新“本期新增数”，**绝不覆盖**人工填写的字段（人工综合排序、负责人、解决方案、迭代周期）。新问题则新增一行。

### 3.5 文档
- **周报文档**：每次周度打标完成后自动创建飞书文档，标题包含周期标识，内容为当次 Bot 通知的完整信息。
- **月报文档**：每次月度分析完成后自动创建飞书文档，包含 Top 问题详情、大客户占比、典型反馈原文、建议关注点，以及本次标签进化的详细内容。

### 3.6 可视化仪表盘
飞书多维表格原生仪表盘，图表自动刷新。至少包含：
- NPS 满意占比趋势
- 负反馈总量趋势
- 不满意原因分布
- 评分分布
- Tag1 问题性质分布与趋势
- Tag2 模块满意度排名
- 大租户反馈占比趋势

## 4. 标签体系使用规则

### 4.1 三层标签的含义

| 层级 | 含义 | 示例 |
|------|------|------|
| **Tag1 问题性质** | 问题本质类型，决定处理路径 | 性能提升 |
| **Tag2 功能模块** | 问题归属的功能/业务域 | 打卡模块 |
| **Tag3 具体问题** | 从用户原话提炼的具体现象 | 定位失败 |

### 4.2 标签的创建与管理
- Tag1 默认 7 类，管理员可在配置中心增删改。
- Tag2/Tag3 由 AI 动态创建，用户也可在多维表格中手动新增。
- 反馈列表引用标签后，**修改标签名称会自动同步到所有引用它的反馈**。

### 4.3 Tag1 权限
Tag1 子表仅限管理员编辑，普通成员只读。若有人在表格中直接修改 Tag1，系统检测到后通过 Bot 询问管理员是否同步。

### 4.4 标签缓存

为避免每次打标都查询标签体系，系统采用 **5 分钟内存缓存**机制：

- 首次打标时加载全量标签到内存
- 5 分钟内重复打标直接读缓存
- 标签变更（合并/拆分/手动修改）后自动失效缓存
- 缓存失效后下次打标重新查询

## 5. 核心流程

### 5.1 数据拉取与 AI 打标（每周）

**触发**：用户配置的定时任务，默认每周一 09:00 自动执行。也可通过 Bot 对话手动触发。

**数据源模式**：
系统支持两种数据源接入方式：
- **API 拉取**：调用配置的接口地址，使用 API Key 和时间范围规则自动拉取。
- **Excel 上传**：用户手动上传 Excel 文件。

**优先级规则**：Excel 上传具有最高优先级。若用户上传了 Excel 文件，系统优先分析 Excel 数据，忽略 API 配置。Excel 无数据或未上传时，才走 API 拉取流程。

**Excel 上传的三种入口**：
1. **配置页上传**：用户在配置中心 Tab 1 上传 Excel 文件，上传后自动触发打标流程。
2. **人工导入后对话执行**：用户先在配置页上传 Excel，然后在 Bot 群聊中输入指令手动触发打标。
3. **Bot 对话直接导入并执行**：用户在 Bot 群聊中发送文件并 @机器人，机器人接收文件后自动导入并执行打标。

**流程步骤**：
1. **获取反馈**：根据数据源模式获取反馈数据。
   - Excel 模式：读取上传的 Excel 文件。
   - API 模式：调用配置的 API 接口拉取上一周的新反馈。
2. **去重**：与表格中已有的反馈 ID 对比，过滤重复数据。
3. **补充租户名**：查找每条反馈对应的租户名称。如果是新租户，自动查询并写入租户信息表。
4. **语言翻译**：系统自动检测反馈原文语言。若为非中文，AI 自动将其翻译为中文，并记录在“翻译后文本”字段。后续分析基于中文内容进行。
5. **AI 打标**：AI 逐批分析反馈，给出 Tag1/Tag2/Tag3 标签、置信度、是否需要查日志。
   - 标签优先匹配已有标签，无则自动创建。
   - 置信度低于阈值或 AI 觉得拿不准的，标记为“待审核”。
   - 描述卡顿/白屏等技术现象且无法从文字判断原因的，标记为“需查日志”。
6. **结果写入表格**：所有结果一次性写入飞书多维表格。
7. **发送 Bot 通知**：向配置的飞书群发送周报消息卡片。

### 5.2 月度分析与标签进化（每月）

**触发**：用户配置的定时任务，默认每月 1 日 09:00 自动执行。

**流程**：
1. **标签自进化**（先于 Top 问题分析执行）：
   - **合并**：发现两个同层级标签语义几乎相同，AI 自动合并，保留高频名称，更新所有历史反馈的引用。
   - **拆分**：发现某 Tag2 下的 Tag3 超过 10 个且能明显分成多类，AI 自动拆分成更细的 Tag2，迁移对应 Tag3。
   - 冷门标签保留，不做处理。
2. **生成 Top 问题表**：基于进化后的标签，统计每个 Tag2+Tag3 组合的反馈数，按大租户反馈数降序排列，取前 20-30 条写入表格。已存在的问题只更新“本期新增数”，绝不覆盖人工填写的字段。
3. **生成会议文档**：创建飞书月报文档，详细列出每个 Top 问题的数据、典型反馈原文、建议关注点，以及本次标签进化的完整记录。
4. **发送 Bot 通知**：向配置的飞书群发送月报消息卡片。

## 6. Bot 通知消息内容

### 6.1 周报消息（每周）

```
📊 【Feelgood 打标周报】2026 年第 25 周

本周拉取：47 条负反馈
AI 已完成打标，待审核：23 条

📋 Top 5 问题：
1. 定位异常 (打卡模块) - 11 次 (23.4%)
2. 加班数据看不到 (加班模块) - 7 次 (14.9%)
3. 审批催办无效 (审批模块) - 5 次 (10.6%)
4. ...
5. ...

📈 评分分布：1 分占 30% | 2-3 分占 20% | 4-5 分占 50%

[审核标签]  [完整看板]  [查看日志平台]

⚠️ 本周待审核量超过 100 条，请及时处理！
（仅在待审核数 > 100 时显示红色警告）
```

- **审核标签**：点击打开多维表格，自动筛选出“待审核”的反馈。
- **完整看板**：点击打开可视化仪表盘。
- **查看日志平台**：仅当本周期有反馈被标记为“需查日志”时才显示，点击跳转到用户配置的日志平台。

### 6.2 月报消息（每月）

```
📈 【Feelgood 月度分析】2026 年 6 月

📋 Top 问题概览：
1. 定位失败 (打卡模块) - 85 次，大租户占 40%
2. 加班数据看不到 (加班模块) - 45 次，大租户占 30%
3. ...
（列出本月 Top 问题前 3-5 条摘要）

[Top 问题表]  [查看会议文档]  [可视化仪表盘]

🔄 本期标签自进化：合并标签 3 组，拆分标签 2 组，详情已写入会议文档
```

- **Top 问题表**：点击打开多维表格的 Top 问题表。
- **查看会议文档**：点击打开自动生成的月报飞书文档。
- **可视化仪表盘**：点击打开可视化仪表盘。

### 6.4 NPS 分析报告卡片

月度分析完成后，系统生成 NPS 分析报告卡片，包含：

- **概览指标**：总反馈数、NPS 得分、平均分
- **评分分布**：推荐者/被动者/贬损者数量与百分比，各分数详细柱状图
- **TOP 问题**：Top 5 问题标签按钮
- **标签概览**：Tag1 分布统计
- **操作按钮**：查看多维表格 / 向机器人提问

### 6.5 机器人命令
用户在群内 @机器人 可使用以下命令：
- `/nps help` — 显示帮助信息
- `/nps status` — 查看当前配置状态
- `/nps tag` — 手动触发打标流程（用于 Excel 上传后或手动补标）

## 7. 配置中心

配置中心分为三个 Tab 页，部署在飞书应用内，自动获取用户身份。

### Tab 1：连接与集成
- 飞书应用凭据（App ID、App Secret）
- 多维表格（新建或绑定已有）
- **数据源配置**
  - API 模式：接口地址、API Key、查询参数模板（支持 `{{start_unix}}` 等时间占位符）、时间范围规则
  - Excel 上传：文件上传区域，上传后自动覆盖 API 模式优先级
- Webhook 地址展示（供用户自行配置到数据源后台）
- **安全说明**：App Secret、API Key 等敏感信息将加密存储，不同用户配置完全隔离

### Tab 2：AI 与标签
- AI 模型（下拉选择预设模型，或自定义 API 地址和模型名，填入 Token）
- Tag1 一级标签管理（列表展示，可增删改，默认 7 类）
- Tag2 预设（可选，输入功能模块结构供 AI 参考）
- 打标规则（置信度阈值，默认 0.8；大租户定义，默认 A4/A5/A6）

### Tab 3：任务与运营
- 数据拉取周期（下拉选择，支持自定义 Cron，默认每周一 09:00）
- 月度分析周期（下拉选择，支持自定义 Cron，默认每月 1 日 09:00）
- 日志平台 URL（可选，支持 `{{userId}}` 等占位符）
- 通知群（输入飞书群 ID，多个用英文逗号分隔，附“测试发送”按钮）
- 表格管理员（输入飞书用户 ID，多个用英文逗号分隔，仅所有者可修改）
- “立即执行”按钮（手动触发一次完整流程）

## 8. 标签自进化规则

每月分析时，AI 自动检查标签体系的合理性：

| 操作 | 条件 | 执行方式 |
|------|------|----------|
| **合并** | 两个同层级标签（Tag2 或 Tag3）语义几乎相同 | AI 自动合并，保留高频名称，更新所有历史反馈的引用 |
| **拆分** | 某 Tag2 下的 Tag3 超过 10 个，且能明显分成 2 个以上子类 | AI 自动创建新 Tag2，迁移对应 Tag3，更新历史反馈 |
| **保留** | 使用次数很少的标签 | 不做任何处理，保留在表中 |

## 9. 未来规划

- Tag1 权限控制：通过飞书高级权限实现 Tag1 子表仅管理员可编辑。
- 打标性能优化：当标签量增长至数百级别时，引入分层打标与向量检索，减少 AI 成本并提升准确率。
