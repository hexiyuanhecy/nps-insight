# 飞书免登录授权修复 - 规格文档

## Overview
- **Summary**: 按照飞书官方免登授权最佳实践重构授权流程：飞书客户端内打开应用时直接跳转到授权页面实现免登（无需用户确认），外部浏览器中点击授权按钮后新窗口打开授权页面。
- **Purpose**: 解决用户反馈的"飞书内点击授权跳转到浏览器并且报错"问题，采用飞书官方推荐的免登方案，简化实现，提升可靠性。
- **Target Users**: 在飞书客户端内使用 NPS Insight 的用户

## Goals
- 飞书 Webview 环境内自动免登授权（跳转授权页后自动回调，用户无感知）
- 飞书内授权不跳转到外部浏览器
- 外部浏览器环境需点击授权按钮才跳转 OAuth
- 授权成功后正确保存 token 并展示用户信息
- 简化实现，减少对 JSAPI 的依赖，提高可靠性

## Non-Goals (Out of Scope)
- 不改变授权回调的后端逻辑
- 不改变 token 存储结构
- 不新增飞书权限范围
- 不修改其他配置页面的功能
- 不移除 JSAPI 支持（保留作为可选方案）

## Background & Context

### 当前问题
用户反馈：
1. 在飞书内点击授权会跳转到浏览器里
2. 跳转后报错

### 根因分析
通过代码审查和官方文档对比，发现以下问题：

1. **授权 URL 域名不统一**：
   - 当前代码使用 `https://open.feishu.cn/open-apis/authen/v1/authorize`
   - 官方文档推荐使用 `https://accounts.feishu.cn/open-apis/authen/v1/authorize`
   - 可能导致授权页面异常

2. **过度依赖 JSAPI 导致复杂且不可靠**：
   - 当前方案尝试通过 `lark.oauth.getAuthCode()` 实现静默授权
   - JSAPI 初始化需要签名、配置域名白名单等，步骤复杂
   - JSAPI 加载时序、初始化失败等问题导致授权流程不稳定
   - 环境检测不准确时，飞书环境被误判为浏览器环境，走 `window.open` 导致跳转到外部浏览器

3. **飞书内免登的正确姿势（官方推荐）**：
   - 根据飞书官方文档："在飞书客户端内打开网页应用时，可以直接跳转无需确认"
   - 也就是说，只要在飞书内跳转到授权页面，飞书会自动完成授权并回调，用户无需点击任何按钮
   - 这才是真正的"免登"，比 JSAPI 方案更简单可靠

### 飞书免登授权标准流程（官方推荐）

**飞书客户端内：**
1. 检测到飞书环境且未授权
2. 直接用 `window.location.href` 跳转到授权页面
3. 飞书客户端识别到是在飞书内打开，自动免登（用户无感知）
4. 授权成功后回调到应用，携带 code 参数
5. 后端用 code 换取 user_access_token，完成授权

**外部浏览器：**
1. 检测到非飞书环境且未授权
2. 用户点击"前往飞书授权"按钮
3. 新窗口打开授权页面（`window.open`）
4. 用户手动点击授权
5. 授权成功后回调到应用，携带 code 参数
6. 后端用 code 换取 user_access_token，完成授权

## Functional Requirements

### FR-1: 飞书环境自动检测
- 页面加载时通过 User-Agent 检测是否在飞书 Webview 环境
- 检测逻辑简单可靠，不依赖 JSAPI 注入时机
- 飞书环境标记：User-Agent 包含 `Lark` 或 `Feishu`

### FR-2: 飞书环境自动免登
- 飞书环境下，检测到未授权时自动跳转到授权页面
- 使用 `window.location.href` 在当前页面跳转（不打开新窗口）
- 用户无感知，飞书客户端自动完成授权并回调
- 跳转前显示"正在授权..."状态提示

### FR-3: 授权按钮行为区分环境
- **飞书环境**：点击授权按钮时，直接跳转授权页面（当前页面跳转）
- **外部浏览器**：点击授权按钮时，在新窗口打开授权页面

### FR-4: 授权 URL 规范
- 使用飞书官方推荐的授权域名 `accounts.feishu.cn`
- 参数完整：`client_id`、`response_type=code`、`redirect_uri`、`scope`、`state`
- `redirect_uri` 正确 URL 编码

### FR-5: 授权状态展示与错误提示
- 清晰展示当前授权状态（未授权/授权中/已授权）
- 授权失败时显示具体错误信息
- 提供重试按钮
- URL 中的错误参数自动解析并提示

### FR-6: 保留 JSAPI 支持（可选降级）
- 保留 JSAPI 初始化和 `getAuthCode` 能力
- 作为可选方案，不做为主要授权路径
- 主要路径使用直接跳转授权页面的方案

## Non-Functional Requirements

### NFR-1: 性能
- 环境检测在 10ms 内完成
- 授权跳转在页面加载后 500ms 内触发（飞书环境）
- 授权状态查询响应时间 < 500ms

### NFR-2: 可靠性
- 飞书环境免登成功率 > 99%
- 授权失败有明确错误提示和降级方案
- 网络异常时有友好的错误提示

### NFR-3: 可维护性
- 授权逻辑清晰，减少复杂度
- 代码注释清晰，关键步骤有日志输出
- 移除不必要的 JSAPI 复杂度

## Constraints

### 技术约束
- 必须使用飞书官方 OAuth 授权流程
- 必须兼容现有后端授权 API（`/api/user-resource`）
- 不能改变现有的 token 存储结构
- 必须使用 TypeScript，禁止 `any` 类型

### 业务约束
- 必须保留外部浏览器 OAuth 授权方式
- 授权流程必须符合飞书开放平台规范
- 不能申请新的飞书权限

## Assumptions
- 用户已在飞书开放平台正确配置了应用（App ID、App Secret、重定向 URL 白名单）
- 用户已在配置中心正确填写了飞书应用配置
- 飞书客户端版本支持免登授权
- 服务器可以正常访问飞书开放平台 API

## Acceptance Criteria

### AC-1: 飞书环境自动免登成功
- **Given**: 用户在飞书客户端内打开应用，且尚未授权
- **When**: 页面加载完成，检测到飞书环境
- **Then**: 系统自动跳转到飞书授权页面
- **Then**: 飞书客户端自动完成免登（用户无感知）
- **Then**: 回调到应用页面，显示用户信息（头像、姓名）
- **Verification**: `human-judgment`

### AC-2: 飞书内授权不跳转到外部浏览器
- **Given**: 用户在飞书客户端内，尚未授权
- **When**: 触发授权（自动或手动点击）
- **Then**: 在飞书 Webview 内完成整个授权流程
- **Then**: 不跳转到系统浏览器
- **Verification**: `human-judgment`

### AC-3: 飞书内手动点击授权正常
- **Given**: 用户在飞书客户端内，尚未授权
- **When**: 用户点击"前往飞书授权"按钮
- **Then**: 在当前页面跳转到授权页面
- **Then**: 飞书自动免登并回调
- **Then**: 显示授权成功状态和用户信息
- **Verification**: `human-judgment`

### AC-4: 外部浏览器点击授权打开新窗口
- **Given**: 用户在外部浏览器中打开应用，尚未授权
- **When**: 用户点击"前往飞书授权"按钮
- **Then**: 在新窗口打开飞书 OAuth 授权页面
- **Verification**: `human-judgment`

### AC-5: 浏览器环境不自动跳转授权
- **Given**: 用户在外部浏览器中打开应用，尚未授权
- **When**: 页面加载完成
- **Then**: 不自动跳转到授权页面
- **Then**: 授权状态显示"未授权"
- **Then**: 用户可以手动点击授权按钮
- **Verification**: `human-judgment`

### AC-6: 授权成功后状态正确展示
- **Given**: 用户完成授权（任意方式）
- **When**: 返回配置中心页面
- **Then**: 显示用户头像、姓名、OpenID
- **Then**: 显示 Token 剩余有效期
- **Then**: 提供"退出授权"按钮
- **Verification**: `human-judgment`

### AC-7: 授权失败有明确错误提示
- **Given**: 用户授权过程中发生错误
- **When**: 错误发生
- **Then**: 显示具体的错误信息（如"App ID 不正确"、"重定向 URL 未配置"等）
- **Then**: 提供重试按钮
- **Verification**: `human-judgment`

### AC-8: 退出授权后可以重新授权
- **Given**: 用户已授权
- **When**: 用户点击"退出授权"按钮
- **Then**: 授权状态变为"未授权"
- **Then**: 可以重新发起授权
- **Verification**: `human-judgment`
