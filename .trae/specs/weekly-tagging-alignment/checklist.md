# 周打标流程对齐 - Verification Checklist

## 节点 1：任务触发
- [ ] 定时任务可按配置周期触发
- [ ] Bot 命令 `/nps tag` 可手动触发打标
- [ ] 配置页「立即执行」按钮可手动触发

## 节点 2：数据源读取
- [ ] Mock 模式下正确生成模拟反馈数据
- [ ] API 模式下正确拉取对应周期数据
- [ ] 读取字段与反馈列表字段一一对应

## 节点 3：数据去重
- [ ] 与反馈列表中反馈 ID 重复的数据被完全过滤
- [ ] 无重复数据写入表格
- [ ] 去重后数量与预期一致

## 节点 4：租户信息补充
- [ ] 已有租户自动补全名称、规模等字段
- [ ] 新租户自动查询信息并新增到租户信息表
- [ ] 租户信息无重复创建

## 节点 5：语言检测与翻译
- [ ] 中文反馈不翻译，translatedContent 为空
- [ ] 非中文反馈自动翻译为中文，写入「翻译后文本」字段
- [ ] 后续打标基于中文内容执行

## 节点 6：标签缓存加载
- [ ] 首次打标全量加载标签到内存
- [ ] 5 分钟内重复打标直接读取缓存，不重复查表
- [ ] 标签变更后缓存自动失效，下次重新加载

## 节点 7：AI 打标处理
- [ ] 优先匹配已有标签，无匹配则自动创建 Tag2/Tag3
- [ ] 每条反馈生成 0-1 之间的置信度数值
- [ ] 置信度低于阈值的反馈标记为「待审核」
- [ ] 卡顿/白屏等技术类反馈标记为「需查日志」
- [ ] 打标状态统一更新为「已打标」

## 节点 8：结果写入表格
- [ ] 所有打标字段批量写入，无遗漏（tag1/tag2/tag3/confidence/needLogCheck/reviewNeeded/translatedContent/status）
- [ ] TAG1 表写入 Tag1 标签数据
- [ ] TAG2 表写入 Tag2 标签数据
- [ ] TAG3 表写入 Tag3 标签数据
- [ ] 标签使用次数正确递增
- [ ] 标签表包含大租户占比统计字段
- [ ] 标签表包含平均分统计字段

## 节点 9：周报文档生成
- [ ] 文档标题包含周期标识（如 2026年第25周）
- [ ] 内容与 Bot 通知信息一致，包含完整统计数据
- [ ] 内容包含：反馈总数、NPS 分数、评分分布、Top 问题、待审核数
- [ ] 每次打标创建新文档，不覆盖历史文档

## 节点 10：Bot 周报通知
- [ ] 卡片格式与 PRD 定义完全一致
- [ ] 数据准确：反馈总数、待审核数、Top5 问题、评分分布
- [ ] 「审核标签」按钮跳转筛选后的待审核列表
- [ ] 存在需查日志反馈时显示「查看日志平台」按钮
- [ ] 待审核数 > 100 时显示红色警告提示
- [ ] 每次周打标只发送一条通知消息
